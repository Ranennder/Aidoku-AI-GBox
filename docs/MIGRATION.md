# Перенос с Mihon AI

Для постоянного обмена историей между телефонами используй
[облачную синхронизацию через Koofr / WebDAV](HISTORY_SYNC.md).
Она работает без ПК и отдельно от разового импорта резервной копии.

## Прямой импорт на iPhone

1. В Mihon AI создай резервную копию со всеми нужными разделами, включая историю, категории, главы, трекеры и настройки. Передай `.tachibk` или `.proto.gz` на iPhone через приложение «Файлы». Поддерживается также несжатый protobuf; предел исходного и распакованного файла — 256 МиБ.
2. На ПК запусти Suwayomi Server и установи те же совместимые расширения источников. Добавь подключение этого сервера в источниках Aidoku AI. Mihon AI Companion улучшает изображения; Suwayomi хранит каталог и запускает расширения.
3. В Aidoku AI открой **Настройки → Резервные копии → + → Импорт из Mihon** и выбери файл. Можно также открыть бэкап через меню «Поделиться» в «Файлах».
4. Проверь количество записей и выбери подключение Suwayomi. Опция **Восстановить этот бэкап в Suwayomi** отправляет исходный файл выбранному серверу и ждёт завершения восстановления. Если тот же бэкап уже восстановлен через WebUI, выключи опцию. Настройки сервера не перезаписываются.
5. Нажми **Импортировать библиотеку и историю**. Соответствия строятся по точным исходным ID источников и адресам манги/глав. Книги с одинаковыми названиями не смешиваются. Сохраняются даты чтения, прочитанные главы и прогресс с переводом нулевой нумерации страниц Mihon в нумерацию Aidoku.

Импорт объединяется с существующей библиотекой. При совпадениях сохраняются категории, отметка прочитано, самый дальний прогресс и последняя дата чтения. Если имя категории Mihon совпадает с группой фильтров Aidoku, импорт получает отдельную обычную категорию с суффиксом «(Mihon)»; существующая группа сохраняется. Перед объединением создаются резервные копии текущего состояния и объединённых данных. Обновление базы выполняется одной транзакцией с сохранением существующих объектов, локальных файлов и позиций чтения у остальных записей.

Категории на сервере Suwayomi тоже объединяются: встроенное восстановление запускается без замены категорий, затем после точного сопоставления манги добавляются категории и связи из бэкапа. Существующие категории и связи не удаляются, даже если раздел категорий отсутствует в бэкапе. Категории с точным совпадением имени используются повторно; новые добавляются в конец списка без изменения настроек существующих категорий. При ошибке или отмене может успеть добавиться часть новых связей; повторный импорт завершает добавление без создания дублей. Неизвестные категории не сопоставляются по номеру или похожему имени. Выключенная опция восстановления на сервере оставляет его категории без изменений.

История глав, которые больше не доступны на сервере, получает отдельный архивный идентификатор и сохраняет метаданные и дату чтения. Такие главы нельзя открыть до восстановления источника. При повторном импорте точное совпадение исходного адреса заменяет архивный идентификатор настоящим ID, сохраняя прогресс.

Повторный импорт сохраняет это соответствие и после обновления списка глав в Aidoku: архивная запись объединяется с настоящей главой вместе с историей и сессиями чтения.

Закладки глав и внешние записи трекеров восстанавливаются в Suwayomi. В Aidoku добавляется связь с трекером Suwayomi для соответствующей манги. Самостоятельные Android-настройки, заметки, суммарное время чтения и неизвестные поля форка сохраняются в исходном файле: у них нет полного эквивалента в модели Aidoku. Авторизация внешних трекеров на iPhone выполняется отдельно. APK расширений и сами изображения страниц в бэкап Mihon не входят.

Полный оригинал сохраняется на устройстве и доступен кнопкой **Экспортировать исходный бэкап Mihon** на экране импорта. Для включения оригиналов в новый `.aib` включи **Чувствительные настройки** при создании резервной копии: исходный Android-файл может содержать параметры авторизации. Старые резервные копии Aidoku остаются совместимыми; поле с оригиналами необязательно.

Поддержка протокола восстановления проверена по Suwayomi **v2.4.2366**: GraphQL multipart upload, выборочные флаги и статус задания. Отключение встроенного восстановления категорий и API их безопасного добавления проверены также по **v2.2.2100**. Для старого сервера без этого API сначала восстанови бэкап в его WebUI, затем выключи опцию восстановления на сервере в Aidoku. Поведение импорта через WebUI определяется версией сервера; защита существующих категорий выше относится к встроенному импорту Aidoku AI.

## Расширения и библиотека через ПК

1. Создай бэкап в Mihon AI (`.tachibk`). Он содержит библиотеку и прогресс, но не APK расширений и не скачанные изображения.
2. Установи [Suwayomi Server для Windows](https://github.com/Suwayomi/Suwayomi-Server/releases). Сервер запускает совместимые расширения Mihon. Установи в его WebUI используемые репозитории и расширения.
3. Восстанови исходный бэкап Mihon через встроенный импорт выше или WebUI Suwayomi. Дождись завершения восстановления и проверь библиотеку, источники и прогресс.
4. В Aidoku AI открой добавление источника, выбери встроенный Suwayomi и укажи адрес ПК, обычно `http://IP-ПК:4567`. iPhone должен иметь доступ к этому адресу. Введи логин, если он настроен на сервере.
5. Библиотека сервера остаётся основным каталогом. В списках доступны популярное/новинки установленных источников; в фильтрах поиска можно выбрать источник. После изменения набора расширений обнови источник в Aidoku. Установка расширений, их настройки и специальные фильтры доступны в WebUI сервера.
6. Для синхронизации прогресса подключи встроенный трекер Suwayomi для соответствующего сервера. Наличие книг в каталоге сервера само по себе не означает импорт всех книг в локальную библиотеку Aidoku.

ПК нужен и для источников Suwayomi, и для улучшения страниц Companion. Это отдельные серверы: по умолчанию Suwayomi — порт 4567, Companion — 8765. Нативные WASM-источники Aidoku продолжают работать самостоятельно. Все установленные совместимые источники доступны через мост; работоспособность каждого расширения всего сообщества не проверена.

## Общий формат бэкапов

Из корня репозитория, с Python 3.10+:

```powershell
python tools/migration/migrate.py import my-backup.tachibk portable.json
python tools/migration/migrate.py inspect portable.json
python tools/migration/migrate.py import aidoku-backup.aib aidoku-portable.json
```

Формат `manga-migration`, версия 1, содержит источники, категории, мангу и состояния глав. Идентификаторы Mihon сохраняются как строки: преобразование 64-битного source ID в JavaScript Number потеряет точность. Кроме общих данных архив сохраняет исходный бэкап целиком с SHA-256, включая неизвестные поля форка.

Для точного извлечения исходного файла:

```powershell
python tools/migration/migrate.py restore-original portable.json restored.tachibk
```

Конвертер не угадывает соответствия по названию или номеру главы: одинаковые названия могут принадлежать разным источникам. Чтобы получить нативный `.aib` из Mihon, нужны проверенные идентификаторы источника, манги и глав в Aidoku/Suwayomi:

```powershell
python tools/migration/migrate.py mapping-template portable.json mapping.json
# Заполни mapping.json действительными идентификаторами назначения.
python tools/migration/migrate.py export-aidoku portable.json migrated.aib --mapping mapping.json --report report.json
```

После восстановления Mihon-бэкапа на Suwayomi соответствия можно получить автоматически:

```powershell
python tools/migration/migrate.py map-suwayomi portable.json server-mapping.json --server http://IP-ПК:4567 --aidoku-source-id suwayomi-ИДЕНТИФИКАТОР
python tools/migration/migrate.py export-aidoku portable.json migrated.aib --mapping server-mapping.json --report report.json
```

`--aidoku-source-id` — настоящий ключ уже добавленного подключения Aidoku, а не числовой ID расширения Mihon. Чтобы найти ключ, экспортируй небольшой бэкап Aidoku после добавления подключения, преобразуй его командой `import`, затем `inspect`: значение находится в `sources[].native_id`. Для авторизации на сервере используются переменные окружения `AIDOKU_SUWAYOMI_TOKEN`, `AIDOKU_SUWAYOMI_COOKIE` или `--username` вместе с `AIDOKU_SUWAYOMI_PASSWORD`; в файл соответствий они не записываются. Полная справка: `map-suwayomi --help`.

Команда только читает инвентарь сервера. Сопоставление проверяет исходный source ID и URL, затем URL глав; отсутствующие или неоднозначные записи требуют исправления. Для уже подготовленного снимка предусмотрен `--inventory snapshot.json` вместо `--server`.

Экспорт `.aib` переносит общие разделы библиотеки, категорий, глав и истории. Настройки ридера, трекеры, заметки, закладки и поля без эквивалента остаются в переносимом архиве; ограничения перечисляются в отчёте. Перевод прогресса учитывает разницу между нулевым индексом страницы Mihon и счётчиком Aidoku. Обратное создание изменённого `.tachibk` не реализовано; `restore-original` возвращает исходные байты.

Сначала создай отдельный бэкап текущего Aidoku: восстановление разделов `.aib` заменяет существующие разделы, это не слияние. Конвертер не перезаписывает уже существующие файлы. Переносимый JSON включает исходные приватные настройки, если они были в бэкапе; его не нужно добавлять в Git.

## Подключение AI

1. Запусти свой Mihon AI Companion на ПК и подключи iPhone к той же локальной сети. ПК может быть подключён к роутеру кабелем, а iPhone — по Wi-Fi.
2. В Aidoku AI: настройки → чтение → **AI на компьютере**.
3. Оставь адрес пустым: при открытии настроек начнётся поиск ПК. Разреши доступ к локальной сети в системном запросе iOS. После успешного поиска появится найденный адрес; доступный токен сопряжения Companion используется автоматически.
4. Если ПК не найден, нажми **Найти ПК** или **Найти ПК заново**. Проверь, что Companion запущен и брандмауэр ПК разрешает подключение. Если доступ к локальной сети был запрещён, включи его в настройках iPhone → Aidoku AI и повтори поиск. Кнопка **Отмена** или выход из настроек прекращает поиск.
5. Включи **Улучшать страницы на ПК**, выбери быструю или детальную модель и проверь соединение. Проверка `/health` подтверждает доступность сервера; токен проверяется при обработке страницы.
6. Для нестандартного порта, другой сети или уже полученного в Mihon HTTPS-туннеля введи адрес и токен вручную. Ручной адрес сохраняется при обычном открытии настроек. Нажатие **Найти ПК** переключает на автоматический адрес только после успешного поиска; при ошибке ручной адрес остаётся. Введённый вручную токен имеет приоритет над найденным.
7. Открой главу. ПК обрабатывает и длинные страницы: максимальная высота в настройках ограничивает только локальное улучшение на iPhone. В разделе **Последний ответ ПК** отображаются размеры отправленной и полученной картинки, время запроса и дата последнего результата, включая предзагрузку. Для сравнения деталей увеличь страницу.

Предзагрузка готовит обработанные страницы в кэше. При ошибке AI показывается оригинал; он не сохраняется как успешно улучшенный результат. Изменение сервера, токена или модели создаёт отдельные ключи кэша. PNG-кодирование выполняется в фоне; сеть использует асинхронные запросы.

С версии 0.9.12 при включённом AI на ПК читалка в фоне готовит текущую главу и затем следующую, не дожидаясь конца чтения. Сначала обрабатывается открытая страница, затем оставшиеся страницы текущей главы и следующая глава. Если глава открыта с середины, пропущенное начало также подготавливается. При прокрутке видимая страница получает приоритет. Готовые результаты сохраняются в дисковом кэше; полностью декодированные две главы в памяти не удерживаются. Подготовка отменяется при смене качества или выходе из читалки. Для работы Companion должен быть включён и доступен по сети.

Фоновая подготовка поддерживает сетевые страницы и локальные файлы изображений, включая временные файлы исходных изображений источника. Страницы внутри ZIP и старые встроенные base64-страницы обрабатываются при открытии. Обычный лимит дискового кэша — 500 МБ, поэтому очень большие главы могут вытеснять ранее подготовленные страницы.

Если Companion перезапущен и отклонил автоматически найденный токен, приложение повторно проверяет ПК и получает новый токен. Введённый вручную токен остаётся под твоим управлением. Перезагрузка страницы очищает и результат AI, и соответствующий оригинал, чтобы заново скачать изображение с источника.

При блокировке экрана или переходе в другое приложение автопрокрутка останавливается, сохраняя текущую позицию. После возвращения её можно снова включить кнопкой в читалке.
